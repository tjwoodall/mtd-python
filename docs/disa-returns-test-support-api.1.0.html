Overview

The ISA Returns Test Support API simulates specific behaviours of the live ISA Returns API service to support the integration testing in the sandbox environment.

Use this API to configure test scenarios for the ISA Returns API, including:

  • initiation of test reconciliation reports
  • temporary override of the reporting window

Integration requirements

The integration requirements are as follows:

  • REST API using JSON over HTTPS
  • authentication uses the OAuth 2.0 authorization code grant
  • all API calls require an HMRC-assigned unique identifier (Z-Reference) for each approved ISA manager

Test reconciliation

Generate test reconciliation reports for the ISA Returns API to support integration testing in the sandbox environment.

Generate test reconciliation report

Use the ‘Generate test reconciliation report’ endpoint to trigger the generation of a test reconciliation report for the ISA Returns API.

The API request allows you to specify the number of occurrences for each of the following supported error types:

  • oversubscriptions
  • trace and match failures
  • eligibility failures

Depending on the notification process selected, you will either be notified via Push Pull Notifications Service (PPNS) using the callback URL configured while subscribing to the ISA Returns API or you can query the PPNS API directly using the box ID. The reconciliation report shows the rejected records, including any error messages where applicable. Your application can then use the relevant ISA Returns API endpoint to retrieve and process the generated results.

This allows you to test the notification flow and retrieval of the reconciliation report before integrating with the live service.

Note: Each sample reconciliation report has an upper threshold of 2000 simulated errors per report per Z-Reference. Attempts to exceed this limit will result in an error.

Reporting window

Configure a temporary reporting window for the authenticated Z-Reference.

Override the reporting window

Configure a reporting window for the authenticated Z-Reference. The override lasts for one hour and replaces any existing override for that Z-Reference.

This operation does not change the system clock. When the override expires, normal reporting-period validation resumes.
